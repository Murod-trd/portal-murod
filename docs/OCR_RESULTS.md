# OCR: результаты версии 0.3.0-rc.3

Дата: 01.11.2026. Запуск настоящего изолированного Python worker на 24 синтетических растровых PDF без текстового слоя. Это регрессионный набор: он использовался при настройке, а не независимая приёмка. Файлы содержат обычную узбекскую латиницу, вариант Ö/Ğ/Ş/Ç, узбекскую кириллицу, русский, английский и смешанные строки; два шрифта DejaVu Sans/Serif, чистый вариант и JPEG quality 65 с наклоном 1°.

## Что изменено

- Официальные tessdata_best закреплены commit `e12c65a915945e4c28e237a9b52bc4a8f39a0cec` и SHA-256 каждого файла. Устанавливаются Latin, uzb_cyrl, rus, eng, tur и uzb. Модель Latin занимает около 101 МБ; она входит в worker при сборке, а не в исходный ZIP.
- Растрирование до 3000 px, 300 dpi с ограничением страниц/времени/памяти. Сохраняется встроенный PDF-текст и распознаются изображения под ним.
- Совмещённый и два независимых прохода по системам письма; сопоставление строк по координатам, оценке Tesseract и алфавиту результата. Никаких словарных подмен для правильного ответа на образцах.
- Исправлен вывод TSV при отдельном TESSDATA_PREFIX: нужные форматы включаются флагами Tesseract, без зависимости от внешнего файла configs/tsv.
- Основной текст и дополнительные реально распознанные варианты разделены. Варианты попадают только в нормализованный поисковый индекс. Исходный документ и его байты не меняются.
- Сохраняются ocrQuality/meanConfidence/lowConfidenceLines/profiles; UI показывает предупреждение для отмеченных строк. Уверенность Tesseract не является вероятностью правильного распознавания: высокая оценка тоже может сопровождать ошибку.
- Пустой скан возвращает OCR_NO_TEXT, а не ложный READY. Ошибка не влияет на сохранность оригинала.

## Измерение

Обработано **24** PDF, ошибок процесса **0**. Взвешенная ошибка символов **0.63%**, ошибка слов **2.33%**. Все контрольные запросы нашли нужные тексты с учётом дополнительных гипотез (**100%** на этом наборе).

Медиана **2.98 с/страницу**, p95 **3.34 с**, максимум **3.48 с**. p95 рассчитан методом nearest-rank. Это измерение текущей среды, а не обещанная скорость сервера компании.

Сохраняются ошибки: в одном русском варианте «НОМЕР» превращается в латинские HOMEP; в одном узбекском теряется диакритика. Корректный вариант для поиска может находиться во втором проходе. Все исходные/распознанные строки, confidence и задержки доступны в `verification/ocr-acceptance.json`; ограничения не скрываются общей средней метрикой.

Цели инженерного набора: суммарный CER ≤2%, полнота контрольных запросов ≥95%, отсутствие ошибок процесса. Они достигнуты, но не согласованы как критерий реальных документов. Нужен независимый разрешённый набор компании: низкое разрешение, таблицы/колонки, штампы, старые и большие многостраничные сканы. Рукописный текст и повёрнутые на 90° страницы этим тестом не принимались.

## Воспроизведение

```bash
python scripts/setup_ocr.py --destination .runtime/tessdata-best
python operations/ocr_benchmark.py --models .runtime/tessdata-best --output /tmp/ocr.json --strict
```

Нужны Linux/libseccomp, Poppler, Tesseract и зависимости worker. Этот тест начинается с EXTRACT после предполагаемого допуска и **не проверяет AV**. Настоящий standalone ClamAV/EICAR описан в SECURITY_ACCEPTANCE.md; полная контейнерная цепочка с актуальными сигнатурами здесь не пройдена.

## 14.11.2026: сканы-изображения, ориентация страниц, картинки в DOCX, чертежи

Ветка feat/ocr-scans. Измерено на реальном worker-образе из Dockerfile (Tesseract 5.5.4, те же закреплённые модели), полный стек через HTTPS с ClamAV.

- **Сканы как документы.** Для назначения DOCUMENT принимаются .jpg/.jpeg/.png/.tif/.tiff (WEBP не добавлен). Формат определяется по сигнатуре и декодером Pillow, ограниченным именно этим форматом; пределы: 40 Мпикс и 12000 px на страницу, 800 Мпикс суммарно, число страниц TIFF не больше MAX_OCR_PAGES, анимация и 16-битные режимы отклоняются. Декодирование только в песочнице worker. Оригинал хранится без изменений; OCR идёт по нормализованному серому растру (EXIF-поворот, прозрачность на белом, длинная сторона 3508 px, мелкие растры увеличиваются вдвое).
- **Ориентация.** Страница считается плохой, если взвешенная по символам уверенность объединённого прохода ниже 70 или слов меньше 4 (на прямых страницах 92-96, на неверно повёрнутых 38-43). Тогда пробуются 90/180/270 градусов; выбирается лучший по сумме символов×(уверенность/100)^2 (в измерении 1436 против 292); поворот заменяет исходный только при выигрыше в 1.5 раза. Поворот запоминается для следующих страниц; две страницы подряд без пользы отключают попытки для файла. Попытки не идут за пределы общего дедлайна 500 с (резерв 15 с на каждую оставшуюся страницу); при исчерпании остаётся лучший результат. В quality: rotatedPages, rotations. Новых моделей (osd) нет.
- **Картинки в DOCX.** Из тела документа берутся растровые PNG/JPEG/TIFF: не более 20 штук, 10 МБ каждая, 30 МБ всего, меньше 40 px по короткой стороне или 20000 пикс пропускаются; EMF/WMF/SVG пропускаются. Текст добавляется после основного. Проверки активного содержимого DOCX не менялись.
- **Чертежи.** Для страниц менее 60 слов выполняется разреженный проход (psm 11) по копии без метки разрешения; найденные слова попадают только в поисковые варианты. Если слов менее 20 и вне текста есть графика, дополнительно читаются виды повёрнутые на 90 и 270. Замен по словарю нет. В поисковую свёртку добавлено Ø/⌀ -> o (вместе с ö); ранее проиндексированные документы с буквой ø требуют повторной обработки.

Результаты (одна страница A4 300 dpi, 26 строк): прямая 14.3 с до и 14.7 с после; повёрнутая на 90 градусов: уверенность 38 -> 93, 29 с; на 180: 41 -> 93, 43 с; 270 читается Tesseract сам (15 с). Пик памяти worker 344-347 МиБ (до 344). Растровый чертёж: раньше OCR_NO_TEXT, теперь все подписи найдены, 6-10 с. Регрессионный набор из 24 файлов: ошибка символов 0.55% и слов 1.74% (на main в том же окружении те же значения), полнота 100%; медиана 4.99 с против 3.89 с на main (+1.1 с на коротких страницах из-за разреженного прохода). Ограничения: «Ø200» на тестовом чертеже распознано как «200» (поиск по «Ø200» не находит); для неповёрнутого чертежа Tesseract иногда лучше читает вид 90 градусов, поэтому rotatedPages=1 не всегда означает повёрнутый лист.
