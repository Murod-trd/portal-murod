# ADR 002 — установка на один сервер без отдельного S3

01.11.2026, Asia/Tashkent. Владелец просит комплект для передачи ИТ: подключить сервер/VPN без дописывания кода. ОС существующего сервера неизвестна. Выбран воспроизводимый профиль Linux x86_64 VM/сервер с локальным Docker/Compose; на неизвестную host-ОС автоматически не устанавливается Docker и не изменяется её firewall.

В одноузловом профиле private-files хранит закрытый файловый том вместо обязательного отдельного S3. Это уменьшает число внешних сервисов для 150 сотрудников/десятков документов и позволяет согласованно резервировать БД и байты. Nginx/worker том не получают; все выдачи проходят Python API и серверные права. Поддержка S3 остаётся в backend для отдельного инфраструктурного решения, но стандартный установщик её не использует.

Установка генерирует секреты/ACL, использует закреплённые по digest образы и TLS, выполняет технические проверки с настоящими сервисами на месте и создаёт первую копию. Управляющие инструменты — Python stdlib на хосте; криптография выполняется в API-образе. Согласованная копия требует короткого планового окна. Вариант не обещает отказоустойчивый кластер, нулевой downtime или защиту внешнего канала от DDoS.

Node используется исключительно для статической сборки frontend и только вне сервера: релиз приходит с готовым `frontend-dist/` ([ADR 004](004-no-node-on-server.md)). Сетевой сервер приложения и worker — Python. Изоляция парсера — отдельный ресурсно ограниченный процесс с дополнительным seccomp-фильтром; сеть/сигналы родителю запрещены. AV-проверка оригинала и производного изображения выполняется доверенным supervisor, не парсером.

Смена архитектуры записана как техническое решение для нового требования передачи. Она не отменяет приёмку прав, приватности, восстановления, сети, файлов и независимый пентест. Контейнерное исполнение этого профиля в текущей среде не подтверждено; статус релиза — кандидат до приёмки на стенде.
